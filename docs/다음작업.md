# 다음 작업

이번 작업의 범위는 기존 제작 자료를 VS Code 프로젝트로 정리하는 것이다. PDF 본문을 새로 수정하거나, 공구·부품 정보와 정비 원칙을 모두 반영한 새 책자를 완성한 단계가 아니다.

## 1. 프로젝트 기준점 확인

- 옮겨 둔 원본, 이전 PDF 결과물, 제작 스크립트, OCR, 메타데이터의 실제 위치와 존재 여부를 확인한다.
- 기존 파일과 사용자 변경을 보존하고, 제작 입력과 이전 출력의 목록을 남긴다.
- 실행 환경과 진입 명령을 확인한다. 개인 PC의 절대 경로가 필요한 부분은 설정으로 분리한다.
- 이전 결과물을 프로젝트에서 다시 만드는 경로를 확인한 뒤 보완 작업을 시작한다. 재현 여부를 확인하기 전에는 성공으로 기록하지 않는다.

## 2. 공구·보호 준비물·교환 부품 근거 정리

- 각 본절차와 삽입 참조절차에서 준비물을 추출해 원본 파일·페이지·문구와 연결한다.
- 일반 공구, 보호용 준비물, 특수공구를 구분한다. 일반적인 관행만으로 공구 규격을 채우지 않는다.
- 교환 부품은 “필수 교환”과 “손상 시 교환” 등 원문의 조건을 보존한다.
- 특수공구 품번과 차량 부품번호를 별도 필드로 관리한다.
- 미확인 차량 부품번호는 확인 필요 상태로 남긴다. 차대번호 기반 WPC 자료가 확보된 경우 적용 사양·조회 근거와 함께 검토한다.
- 부품 사진·도해를 준비물과 연결할 때 원본의 부품 지시선과 명칭을 대조한다.

## 3. 정비 원칙 분류

- 원문의 주의·유의·참고·금지·필수·권고 문구와 완료 점검 항목을 수집한다.
- 상자 제목뿐 아니라 실제 문장으로 지시 강도를 판단한다. 예: “참고” 안의 “반드시 교환”은 필수 교환 표식을 보조한다.
- 작업 전 공통 원칙, 해당 단계의 주의사항, 참조 범위의 주의사항, 완료 확인을 나눈다.
- 제조사 지시와 교재 권고를 구분한다. 출처와 적용 범위가 불명확한 내용은 확정하지 않는다.

## 4. 대표 책자로 레이아웃 확인

- 준비물과 필수 교환 조건이 있는 항목을 골라 작업 길잡이 한 쪽에 통합한다.
- 첫장의 부품 사진과 작업 소개를 유지한다. 작업 길잡이가 과밀해지면 핵심 요약과 본문 쪽번호 연결로 정리한다.
- 주의·필수·권고 표시는 기존 1~5차 참조 테두리와 겹치지 않는 체계로 적용한다.
- 해당 단계 직전의 주의 표시와 절차 끝의 완료 확인란을 확인한다.
- 긴 항목명, 중첩 참조, 홀수·짝수 페이지, 흑백 출력에서 읽을 수 있는지 렌더링하여 검토한다.

## 5. 전체 적용과 탐색 연결 재생성

- 대표 항목에서 확인한 형식을 30개 본책에 적용한다.
- 준비물 목록에는 각 책자에서 실제로 수행하는 참조절차의 준비물도 반영한다.
- 참조 진입·복귀 순서, 실제 쪽번호, PDF 링크, 종합 색인을 함께 다시 생성한다.
- 좌측 제본의 양면 여백과 바깥쪽 하단 쪽번호를 전체 출력물에 적용한다.

## 6. 검증과 배포물 작성

- 원본 내용·수치·이미지와 출력물을 대조하고 누락·중복 삽입을 검사한다.
- 모든 참조와 복귀 목적지, 색인 연결, 페이지 수, 인쇄 방향을 점검한다.
- 대표 페이지 외에도 긴 제목·절차 경계·마지막 쪽 등 취약 지점을 실제 렌더링으로 확인한다.
- 자동 검사와 실제 시각 검토의 범위·결과·미확인 사항을 별도로 기록한다.
- 검증된 새 파트별 PDF, 종합 색인, 압축파일을 이전 결과물과 구분하여 만든다. 완료 안내에는 실제 생성한 파일과 남은 제약만 기재한다.

제작 중 판단 기준은 [제작기준.md](제작기준.md)를 따른다. 원문 근거가 없는 부품번호나 안전·정비 수치를 채워 넣는 방식으로 빈칸을 해결하지 않는다.
